Accessibility

What bootstrap-ng does to make its components accessible, and what is still up to you.

Overview and limitations

bootstrap-ng implements Bootstrap 6's interactive components in Angular, following the WAI-ARIA Authoring Practices. Components work with a mouse, touch and the keyboard, and expose their roles and states to screen readers. Every page of this site is tested with axe in light and dark mode, including with menus, popovers and dialogs open.

How accessible your app is still depends on your markup, content and styles. With those done well, you can build apps that meet WCAG 2.2 AA and similar standards.

ARIA roles and states

Components set the roles and states that their pattern needs through their host bindings, so you don't write them yourself. For example, tabs get role="tab", aria-selected and aria-controls; collapse and menu toggles get aria-expanded; and the current page in pagination, breadcrumbs and navs gets aria-current. IDs that link elements together are generated for you.

Keyboard support

Everything you can do with a pointer, you can do with the keyboard. Composite widgets are a single Tab stop, and arrow keys move within them:

@for (row of keyboard; track row.name) { }
Component Keys
{{ row.name }} {{ row.keys }}

Menus and submenus follow the page's direction, so Left and Right swap in right-to-left layouts.

Focus management

Components move focus so that keyboard and screen reader users don't lose their place:

  • Modal dialogs and drawers use the native <dialog> element, which traps focus while open and returns it to the element that opened the dialog when it closes.
  • Closing a menu with Escape returns focus to its toggle.
  • Popovers are rendered at the end of the page, but Tab and Shift+Tab move between the trigger and the popover as if it came right after the trigger.
  • When a dismissible alert closes while focus is inside it, focus moves to the next control on the page.

Live announcements

Screen readers often miss a live region that appears together with its text. So toasts and carousels don't rely on aria-live on their own elements. Instead, they announce through BsLiveAnnouncer, a service that keeps visually hidden live regions on the page:

  • Toasts read their text when shown, politely by default. Set live="assertive" for errors that should interrupt.
  • Carousels announce the new slide when the user changes it, but not during autoplay, as in the WAI-ARIA carousel pattern.

Color contrast

Some colors in Bootstrap 6's default palette, used for buttons, alerts and validation states, may not meet the WCAG 2.2 text contrast ratio of 4.5:1 or the non-text contrast ratio of 3:1, especially on light backgrounds. Test the colors you use and adjust Bootstrap's theme where needed.

Reduced motion

Bootstrap's CSS respects prefers-reduced-motion, which turns off most transitions. bootstrap-ng does the same for the motion it adds: when the user prefers reduced motion, a looping carousel jumps back to its first slide instead of sliding on past the last one, and scrollspy links jump to their section instead of scrolling smoothly.
