Testing

Tips for unit testing Angular components that use bootstrap-ng.

Run tests in a real browser

bootstrap-ng relies on the browser's own elements and APIs, such as <dialog>, ResizeObserver and layout measurements for positioning menus and tooltips. jsdom has no layout engine and lacks some of these APIs, so test components that use bootstrap-ng in a real browser. With the Angular CLI's Vitest runner, set browsers in the test target in angular.json and install Playwright:

bootstrap-ng runs its own unit tests this way, in headless Chromium.

Bootstrap's CSS and transitions

The test build uses the options of your app's build target, so when Bootstrap's CSS is in its styles, tests have it too. Components wait for Bootstrap's CSS transitions before they emit events such as shown and hidden. Without the CSS, nothing has a transition and these events are emitted right away. Find overlays in the document

Query by role and name

Components set the ARIA roles, states and labels that Bootstrap documents, so tests can find elements the way users and assistive technology do. Query by role and accessible name, for example with Vitest's browser locators or Testing Library, and check states such as aria-expanded and aria-selected instead of class names.

Form controls

Form controls such as datepickers, typeaheads and ratings are Angular form controls. Set and read their values through the form control in the test, as you would with a native input. To test typing, change the input's value and dispatch an input event, or use a user-event library.
