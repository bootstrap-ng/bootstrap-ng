Global configuration

Set default values for component inputs once, for the whole app or for part of it.

Overview

Each component with inputs that apps commonly set the same way everywhere, such as tooltip placement, the carousel interval or a translated label, has a provideBs*Config() function. Add it to your application's providers to change the defaults of every instance:

An input you set on a component always wins over the configuration, and options you leave out keep their built-in defaults. Components read their configuration when they are created, so set it before they render, not while the app is running.

For part of an app

The same functions work in a component's or a route's providers. Components in that part of the app use those defaults, merged over the app's own, so you only list what changes:

Popups that services create, such as dialogs from BsDialogService and toasts from BsToaster, use the app's configuration, and the options you pass when opening them win over it. The calendar that a datepicker opens also uses the app's calendar configuration.

Calendars and datepickers

Calendars and datepickers format dates in Angular's LOCALE_ID unless you give them a locale. Datepickers use the calendar configuration too, so one provideBsCalendarConfig() sets the locale, first day of the week and week numbers of both. Configuration functions

Each function takes some of the inputs of its component, with the same names and types. Each configuration also has an interface, such as BsAlertConfig, and an injection token, such as BS_ALERT_CONFIG, for components of your own that want to read it.
