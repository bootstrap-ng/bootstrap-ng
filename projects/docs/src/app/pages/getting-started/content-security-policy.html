Content Security Policy

Run bootstrap-ng under a strict Content Security Policy (CSP), with nonces for Angular's styles and no 'unsafe-eval'.

What bootstrap-ng needs

bootstrap-ng doesn't use eval(), inline scripts or Bootstrap's JavaScript, so it adds nothing to script-src. Its needs are about styles and the files it loads:

  • A few components, such as bs-icon, data tables and the clear button of clearable form controls, have component styles. Angular adds them in <style> elements, which need a nonce or 'unsafe-inline' in style-src.
  • Components set style properties from script, for example to position tooltips, popovers and menus with Floating UI, or to size progress bars. A CSP doesn't block styles set this way.
  • With server-side rendering, the same styles are written as style attributes in the HTML, which style-src-attr controls.
  • Bootstrap's CSS from jsDelivr and icons that bs-icon loads from jsDelivr need their origin allowed.

Server-side rendering

Styles that components bind, such as the width of a stacked progress bar, the fill of a range or the color of a password strength meter, are written as style attributes in server-rendered HTML. A policy without 'unsafe-inline' blocks these attributes until the values change in the browser. Allow them with style-src-attr 'unsafe-inline', which still blocks <style> elements without a nonce. See Server-side rendering for the rest of the setup.

External files

  • Loading Bootstrap's CSS from jsDelivr needs https://cdn.jsdelivr.net in style-src. Bundle it with your app instead to keep style-src 'self'.
  • bs-icon fetches SVG files, from jsDelivr by default, which needs their origin in connect-src. Self-host the icons or bundle them to keep connect-src 'self'.

Trusted Types

Angular supports Trusted Types. bs-icon parses SVG markup by setting innerHTML on an inert <template> and cleans it before use, so a policy with require-trusted-types-for 'script' needs a default Trusted Types policy to show icons.
